# Gleam v1.48.0 security audit

## Scope

Diff: `60e1c1d..fe951c6`. The release shows a signed item's tags in tiers on the approval screen (#254), sends L1 tokens and collectibles to a process that holds no AR (#253), finds the HyperBEAM peers that serve L1 tokens, reads an L1 balance from the host furthest ahead, plays collectible videos, shows received collectibles in activity, and serves the site's Umami tracker from the site.

Surface paths changed, by theme:

- **L1 sends to an empty process.** A node refuses a transaction to a target with no balance, so `core/ao/l1-transfer.ts` sends `L1_ACTIVATION_WINSTON` (1 winston) to a token process that holds no AR, and `estimateL1TransferFee` quotes the reward plus that winston as the fee. `prepareL1TokenTransfer` takes the approved fee and splits it into value and reward; it refuses a fee that can't pay the value. `prepared-check.ts` (`l1FeeSplit`) accepts only a value of 0 or 1 winston, with a reward of exactly the approved fee minus that value, so the transaction costs exactly the fee the user approved and any other value fails as the amount. `summarize` folds the value into the fee it shows. `readL1TokenTransfer` returns the value; a dApp's transfer that carries any AR (`provider.ts`) shows as the plain transaction, not as a token transfer. `transfer.ts` checks the balance against the approved fee rather than the reward. `graphql.ts` reads a transfer carrying the activation winston as a transfer. `create-runtime.ts` quotes the fee for a dApp's L1 send the same way.
- **Approval tag tiers.** `core/ao/tag-tiers.ts` (new, added to `surface.txt` at tier 4) sorts an item's tags into headline (first `Action` with `Quantity`, or a `Type` other than `Message`), addresses, app and protocol tags. Every tag lands in exactly one tier, so none is dropped. A protocol name with an unexpected value is lifted into app tags and marked. `TagTiers.tsx` renders names and values through `UntrustedText`; addresses render through `MemorableAddress`, and "this wallet" is matched on the exact address. `other-tags.ts` adds HyperBEAM's `Variant: ao.N.1` as harmless, so it no longer counts beside a transfer headline; `HARMLESS_TAGS` never names a tag a reader acts on.
- **L1 peers and balances.** `peer-discovery.ts` adds `findL1TokenNodes`, which probes candidates for `L1_CANARY_PROCESS_ID`'s slot. `runtime/peers.ts` stores the passing peers and the shipped nodes that failed, and keeps the last answer when nothing passes. `ao/balance.ts` reads the gateway, those nodes and the user's peer in order of the slot each reports, highest first, with a 1.5 s cut-off. `network.ts` adds `hb.arweave.net` and `up.arweave.net` as L1 nodes. These are public reads with CORS `*`; the host permissions don't change.
- **Gateway errors.** `postTransaction` (`transaction.ts`) turns a rejection body that arweave-js passes as an object into its `error` or `body` string, for display.
- **Build and config.** The mobile CSP adds `media-src https:` for collectible videos (`apps/mobile/index.html`). `check-bundles.mjs` allows `lucide-react` in the popup bundles and drops `tslib` from the passkey page's. ESLint ignores the copied Umami script; the eslint hook passes `--no-warn-ignored`. The lockfile adds `lucide-react` 1.66.0 and drops an unused Vite/Rolldown copy. `user-errors.ts` rewords `networkFeeNeeded`.

Outside the surface: the collectibles gallery and video player, activity rows, `MemorableAddress` layout, i18n strings and the site.

Run: `pnpm vitest run`, tsc on all twelve projects, eslint, `pnpm deps:check`, `pnpm wxt:build`, `pnpm check:bundles`, `pnpm mobile:build`, `pnpm test:smoke`.

## Notes

F-1 is accepted: a peer reaches the list only by publishing an on-chain Location record and answering the canary's slot. A wrong answer changes only the balance the wallet displays. It can't move tokens, and the token process refuses a transfer the real balance can't cover. Before this release the first number from a fixed order already won.

F-2 is accepted: it is 1 winston, once per process, shown inside the fee the user approves, and the node refuses the send without it.

F-3 is accepted: both tags are shown on the screen, and AO messages from aos and HyperBEAM carry one `Action`.

F-4 is accepted: the request carries no cookies and reveals only what an image load from the same host already reveals.

Known limitations: no change.
