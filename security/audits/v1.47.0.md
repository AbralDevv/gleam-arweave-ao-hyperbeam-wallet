# Gleam v1.47.0 security audit

## Scope

Diff: `b64005d..60e1c1d`. The release adds backup sync between devices (#239), fixes seven advisories (#240, #249), shows the whole of cut-off approval text (#249), allows screenshots on mobile outside the import-phrase screen (#250), and carries the dark mode round (#247), a token price chart on Send, saved-site icons in the dApp browser and dependency bumps.

Surface paths changed, by theme:

- **Backup sync.** `core/backup/pull.ts` (new) plans what a write pulls from other installs: only wallets, contacts, added tokens and saved sites, only items this install lacks (wallets matched by address and by id), and never an item this install removed. `runtime/handlers/backup.ts` merges each pulled key with `updateStored`, writes wallets under the session lock and runs `isValidWallet` on them again. Pulled values come from a body the backup key opened and `isValidBackupData` checked strictly, so every item passed its guard. A pull runs only while unlocked. A file under another `backupId` is never written over: setup refuses it and a background write stops with `otherPassword` (GHSA-3p6w-rx85-6pf4). Stop syncing forgets this install's key and leaves the file; delete removes it for every device. `core/backup/file.ts` and `models/backup.ts` add the `removed` list and the new problem; `removedOf` filters `removed`, which the body guard doesn't check.
- **Approval previews.** Data that isn't text shows its size (`approval.ts`, GHSA-857v-rm6w-p5r5). Text cut at 4,096 characters is flagged `dataTruncated` and shows its size and a Show all control (GHSA-m28r-3fwg-rjpp). The whole text comes from `getApprovalData`, which is in `APPROVAL_METHODS` and `EXTENSION` tier, decodes the stored signing input, never the preview, and returns `null` for bytes that aren't UTF-8. The expanded text renders through `UntrustedText` (`SignedDataText.tsx`, `DataItemCard.tsx`, `TransferReview.tsx`). `UntrustedText` now marks U+180F (GHSA-84vg-j9v8-hqrr). The approval window sets the theme on the document (`ApprovalRoot.tsx`), display only.
- **Lock.** The update hook that set a vault with no stored timeout to never is gone (`create-runtime.ts`, `wallet-lifecycle.ts`, GHSA-cpff-vrqw-xfqv). A vault with no stored timeout reads as 1 hour.
- **Provider and sends.** A page read whose grant was revoked while it waited on the network gets an error, not the result (`create-runtime.ts`, `requireGrantStill`, GHSA-pg58-3xpf-c2r2). An accepted send whose activity record fails to write still returns its id (`transfer.ts`, GHSA-p53w-vv7g-gq6v).
- **Reads.** `getTokenPriceHistory` (`reads.ts`) charts only `DEFAULT_TOKEN_REGISTRY` tokens from the configured prices API, rejects an unknown range and is `EXTENSION` tier.
- **dApp browser icons.** The native `pageIcon` (`plugins/dapp-view`, `PageIcon.kt`, `PageIcon.swift`) takes the page's icon links, keeps https ones, fetches up to four with no cookies, follows no redirect to http, and returns only an image type of at most 64 KB as a data URL. The app saves it only when the view's origin still matches the site (`BrowserView.tsx`). `browser-sites.ts` stores it under `local:browserSiteIcons` only if it is a base64 image data URL of at most 90,000 characters, and drops it with the site. Icons render in `<img>`, so an SVG's script never runs. Permatell joins the built-in sites (`address.ts`).
- **Mobile privacy.** `PrivacyScreen.enable` is false at startup (`capacitor.config.ts`). `ImportPhrase.tsx` holds `secureScreen` while open, and `adapters/secure-screen.ts` (new) counts holders: `FLAG_SECURE` on Android, the app-switcher cover on iOS. The iOS screenshot block stays off.
- **Dependencies and CI.** `hash-wasm` 4.12.0 → 4.13.0, which runs the vault's Argon2id: the lockfile integrity matches the registry, and 4.12.0 and 4.13.0 give identical Argon2id output for the vault's parameters and a small-memory case. Tailwind, Vite, React Query, jsdom and Playwright are minor bumps. Every workflow moves `step-security/harden-runner` from 2.22.3 to 2.22.4, still pinned by sha. `surface-exempt.txt` follows the collectibles gallery, send chart and browser icon files.

Outside the surface: dark mode tokens and screens, the collectibles gallery, Points copy, `DESIGN.md` and editor settings.

Run: `pnpm vitest run`, tsc on all twelve projects, eslint, `pnpm deps:check`, `pnpm wxt:build`, `pnpm check:bundles`, `pnpm mobile:build`, `pnpm test:smoke`, a manual check in Chrome of long and binary approval data in light and dark, and of screenshots and the app switcher in the iOS simulator and on Android.

## Notes

F-1 to F-7 came from community reports and are published. F-1 stops new vaults from being set to never, but a vault an earlier update already set to never keeps that value: it can't be told apart from one the user set. The published advisory asks users on the default to pick a time in Settings → Lock & unlock.

F-8 is accepted: the fetch carries no cookies, and only after the user saves the site. Its result goes to the wallet, never back to the page, and is kept only as a small image. A page can already make the same cookieless GET request itself.

Known limitations: no change. `docs/THREAT_MODEL.md` rewrites the auto-lock By design entry, since F-1 removed the update rule it described.
